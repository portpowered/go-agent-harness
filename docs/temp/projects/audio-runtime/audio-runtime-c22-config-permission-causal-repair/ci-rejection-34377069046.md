## Causal diagnosis

The fixture uses a real clock and a device-bound OpenAI replay. The provider
read loop can deliver `response.output_audio.delta` and
`input_audio_buffer.speech_started` immediately after `session.created`,
while `rtcDeviceBindingInferencer` is still starting the asynchronous sink
pump. Before that pump installs its playback controller,
`SessionMedia.InterruptInbound` has no device-clock controller and returns no
truncation boundary. The replay cursor then remains at its expected client
truncate, and the session teardown closes the raw replay connection; strict
replay surfaces the missing event rather than accepting an incomplete trace.

This explains the CI-only scheduling sensitivity without moving the defect
into a shared production path. The C22 manifest explicitly admits only the
Test6 fixture for this repair; production replay/live/gateway/clock changes
remain owned by the other task partitions named in the meta coordination
decision.
